# SimpRTP 运行机制

## 启动阶段

Folia 加载 SimpRTP 后，主类按以下顺序初始化：

1. 识别 Vault、Essentials、PlaceholderAPI 等可选依赖。
2. 读取语言、主配置、经济、效果、位置、权限组等文件。
3. 加载冷却和玩家数据数据库。
4. 建立默认世界、自定义世界、位置和权限组的运行参数。
5. 注册 `/srtp` 指令、事件监听器和权限节点。
6. 如果 PlaceholderAPI 存在，注册 `simprtp` 占位符扩展。

插件不会启动自动更新、统计上报、后台坐标队列或持续区块扫描任务。

## 一次随机传送的完整流程

```text
玩家执行 /srtp
  → 校验权限、世界、冷却、余额和饥饿值
  → 解析默认世界、自定义世界、位置或权限组参数
  → 如配置了等待时间，启动实体调度任务并监听玩家移动
  → 在配置半径内生成候选 X/Z
  → 在目标区域线程加载并检查区块
  → 检查高度、生物群系、脚下方块和可站立空间
  → 失败则换一个候选点，直到达到 MaxAttempts
  → 触发传送前事件
  → 使用 Folia 异步传送 API 移动玩家
  → 播放声音、标题、粒子和药水效果
  → 写入冷却、次数、日志，并触发传送后事件
```

## 坐标与安全检查

- **square**：在方形边界中采样坐标，并排除最小半径以内的中心区域。
- **circle**：以面积均匀方式在圆环内取样，不会让坐标过度聚集在中心。
- **NORMAL**：从世界最高方块附近寻找可站立位置。
- **NETHER**：在配置的 Y 范围内寻找脚下安全、身体空间为空的点。

候选位置还会检查：

- `BlacklistedBlocks` 中的危险方块；
- 配置允许的生物群系；
- `MinY` 与 `MaxY`；
- 玩家脚部和头部是否有空间；
- 尝试次数是否超过 `Settings.MaxAttempts`。

安全方块表使用集合查询，判断成本不会随列表长度线性增长。

## Folia 线程模型

SimpRTP 不使用传统 Bukkit 主线程假设，而是按操作对象选择 Folia 调度器：

- 实体状态和等待倒计时使用玩家实体调度器；
- 指定坐标的世界操作使用区域调度器；
- 全局状态使用全局区域调度器；
- 数据库和非世界计算使用异步调度器；
- 最终移动使用 `teleportAsync`。

这能避免跨区域直接访问世界或实体造成线程所有权异常。

## 数据与重载

玩家随机传送次数、语言选择和冷却数据会持久化。执行 `/srtp reload` 时，插件会重新读取配置、世界参数、权限、效果和指令，但正在进行的玩家操作不应依赖重载完成；生产环境修改大量世界配置时，建议重启。
